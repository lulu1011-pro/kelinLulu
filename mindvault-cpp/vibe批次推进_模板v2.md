# MindVault vibe coding 批次推进模板 v2

> 一套模板跑完全部 AI 增强批次。每批只换一张「批次卡」,不用每批重写 7 轮话术。
> 配合根目录 CLAUDE.md 使用:主流 AI 客户端会自动加载 CLAUDE.md,项目全貌/表结构/约定都在里面,不必在话术里重复。

## 怎么用(30 秒上手)

1. **新会话第一条**:发【第 0 步:开场上下文包】(固定,内容不变)
2. **紧接着发本批的【批次卡】**(卡里已含该批需求 + 约束 + 验收点,直接整段复制)
3. 之后的 2/3/4/6/7 轮,统一用文末【固定轮次话术】,每批都一样
4. **同一会话内换批**:直接说「进入第 N 批」+ 贴第 N 批卡
5. **新开会话**:重发第 0 步 + 对应批次卡,其余照旧

## 批次卡 2:SSE 流式 + query 改写 + token 预算(依赖第 1 批,即已完成的多轮会话)

```text
【需求】这一批做三件事:P0-2 SSE 流式输出、P0-3.1 query 改写、P0-4 token 预算。全部挂在已完成的会话机制上。

【约束】
1. SSE:后端用 Crow 手写 chunked 流,客户端中途断开(关页面/取消)怎么感知、怎么停生成、怎么释放资源,方案里必须先讲清楚再动手
2. SSE:前端用 fetch + ReadableStream 逐块渲染(EventSource 不支持 POST,不要用);中途报错/中断要在界面上明确提示并支持重试
3. query 改写:必须用指代句验证效果,例如先问「什么是 RAG」再问「它和微调有什么区别」再问「那我项目里现在用的是哪种」,第三句要能正确消解指代
4. token 预算:历史超预算时从最老的开始丢,但系统提示词和当前问题永远保留;估算用字符粗估,再用 API 返回的 usage 字段校准,讲清为什么不用精确 tokenizer
5. 复用 P0-1 的会话消息表、并发锁、截断常量;保持 /api/ai/chat 兼容

先不要写代码。先读 ai_routes.h、AIChatPanel.vue、api.ts 和设计文档 P0-2/P0-3.1/P0-4 章节,给落地方案:SSE 怎么在 Crow 里写流、query 改写是独立接口还是 chat 内前置、token 在哪一环算,标出风险点。
```

## 批次卡 3:混合检索 FTS5 + embedding + RRF(无依赖,可与 2 并行)

```text
【需求】这一批做 P1-5 混合检索:笔记切块 → 调 embedding API 存向量 → 检索时 FTS5 关键词路 + 向量语义路双路召回 → RRF 融合排序。

【约束】
1. 切块规则要明确:按标题/段落切,块间重叠窗口多大、为什么;切块不能切断语义完整的段落
2. embedding API 挂了/超时要能降级回纯 FTS5 结果,不能白屏也不能报错给用户,降级要有日志
3. RRF 融合:两路各自排序后怎么算融合分(k 值取多少、为什么),不许先做分数归一化再相加(面试要能讲清 RRF 的好处)
4. 向量存储:SQLite 加 note_chunks 表,文本列存 JSON embedding,不引 sqlite-vec(十万级才考虑,现在纯手写余弦相似度)
5. 仍是零重量级依赖,复用现有 WinHTTP POST 调 embedding

先不要写代码。先读 search_service.h、search_routes.h、database.cpp 和设计文档 P1-5 章节,给落地方案:表结构、切块函数放哪、双路召回+R RF 在哪层做、前端要不要动,标出风险点。
```
