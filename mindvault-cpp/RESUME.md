# MindVault 项目简历

## 核心写作原则

### ❌ 不要这样写
- "使用 AI 生成代码完成开发"
- "通过 Agent 自动实现了功能"
- "借助 AI 工具快速开发"

### ✅ 要这样写
- "设计 AI 协同开发工作流，主导架构决策与代码审查"
- "制定 Prompt 规范与验证策略，确保 AI 输出质量"
- "将 AI 定位为代码实现辅助，本人负责架构设计、逻辑验证与质量把控"

### 关键词策略
| 避免 | 替代 |
|------|------|
| AI 生成代码 | AI 辅助实现 |
| Agent 自动完成 | 人机协同开发 |
| AI 写的 | AI 草拟 + 人工审查 |
| 依赖 AI | 运用 AI 工具链 |
| 提示词工程 | AI 协作规范设计 |

## 项目名称：MindVault — 本地知识库管理系统

### 项目描述
面向个人知识管理场景，设计并开发本地优先的知识库系统，支持 Markdown 编辑、
Wiki 双向链接、FTS5 全文检索。采用 C++ 后端 + Vue3 前端架构，
通过 REST API 前后端分离，实现高效的知识管理体验。

### 技术栈
**后端**: C++17、Crow、SQLite3 (FTS5)、nlohmann/json、CMake
**前端**: Vue 3、TypeScript、Vite、CodeMirror 6、marked、turndown

### 主要工作

1、主导系统架构设计与技术选型
   - 设计 C++ 后端 + Web 前端架构，REST API 前后端分离
   - 选用 Crow 框架（轻量 HTTP，header-only）替代重型方案
   - 采用 SQLite3 + FTS5 实现本地全文检索，无需外部服务
   - 制定 RESTful API 规范（17 个接口），确保前后端解耦

2、实现 SQLite 数据持久层与 FTS5 全文检索引擎
   - 基于 SQLite C API 封装 Database 类，支持参数化查询与事务管理
   - 设计 FTS5 虚拟表与触发器同步机制，实现毫秒级全文搜索
   - 优化 FTS5 配置：独立存储模式 + 增量索引 + snippet 高亮

3、开发 Wiki 双向链接解析与知识图谱构建
   - 实现 [[标题]] 语法解析器（marked 自定义扩展）
   - 设计 link_edges 表存储有向图结构，支持反向链接 O(1) 查询
   - 编辑保存时增量更新链接关系，避免全量重算
   - 前端实现反向/正向链接面板，支持点击跳转

4、构建 Crow HTTP 服务与 REST API
   - 基于 Crow 框架实现 17 个 REST API，支持 JSON 序列化
   - 实现统一错误响应格式（{ok, data, error}）
   - 配置 CORS 策略 + Vite 代理，保障前后端联调
   - 实现笔记 CRUD、回收站、标签管理、文件导入导出

5、开发 Vue3 前端与 Markdown 编辑器
   - 集成 CodeMirror 6 编辑器 + oneDark 主题
   - 实现三种编辑模式（编辑/分栏/预览）+ Markdown 工具栏
   - 开发递归文件夹树组件（FolderTree.vue）、笔记大纲（OutlinePanel.vue）
   - 实现 Ctrl+K 全局搜索弹框、HTML→Markdown 转换、PDF 导出

### 项目成果
- 17 个 REST API，覆盖笔记 CRUD、全文搜索、Wiki 链接、标签、文件导入导出
- FTS5 全文搜索响应时间 < 50ms（万级笔记）
- 完整的前端交互：文件夹树、编辑器、大纲、反向链接、搜索、回收站
- Tokyo Night 主题 + CSS 变量系统 + 过渡动画

## 面试话术准备

### Q: "你项目中 AI 是怎么用的？"
A: "我把 AI 定位为高级代码辅助工具。整个过程中，我做架构决策——
比如选 Crow 不选 cpp-httplib 是因为我评估了两者的路由能力和 header-only 特性；
我定义接口规范——每个 API 的输入输出、错误码都是我先设计好；
AI 负责草拟实现代码，然后我逐模块编译测试，审查边界条件和内存安全。
相当于我当架构师 + 评审者，AI 当执行者。"

### Q: "为什么选择 C++ 而不是更简单的方案？"
A: "两个原因：一是性能，SQLite C API 直接操作没有 ORM 开销，FTS5 全文检索可以做到毫秒级；
二是学习价值，C++ 项目能展示我对内存管理、编译链接、跨平台构建的理解。
当然 Crow 框架是 header-only 的，大大降低了依赖管理的复杂度。"

### Q: "AI 生成的代码你都能看懂吗？"
A: "看懂是最基本的。我的原则是所有上线的代码我都必须能解释每一行。
实际上 AI 生成的代码我通常会修改 30-40%——
比如 SQLite 操作 AI 习惯用字符串拼接 SQL，我会改成参数化查询防注入；
AI 生成的 Crow 路由缺少错误处理，我会补上异常捕获和统一响应格式。
所以 AI 是加速实现，不是替代理解。"

### Q: "如果没有 AI 你能做吗？"
A: "当然，只是慢一些。AI 省的是我查文档和写样板代码的时间。
像 SQLite C API 的回调风格我本来就熟悉，Crow 的路由语法我花半天就学会了。
AI 的价值是让我把精力集中在架构设计和逻辑验证上，而不是在格式化 JSON
这种重复劳动上。"
